# Contributing feedback

Small corrections and broader suggestions both help improve the books. A report
does not need a proposed fix, and uncertainty is welcome: “I cannot follow this
step” is useful feedback.

1. Check [existing issues](https://github.com/eblais/cs341-books-feedback/issues)
   briefly for the same topic. If you find one, add a comment with any new details.
2. Choose [a feedback form](https://github.com/eblais/cs341-books-feedback/issues/new/choose).
3. Give the issue a descriptive title, such as “Missing justification in the
   Merge correctness proof.”
4. Identify the passage and explain your concern. A section title, theorem or
   exercise number, or short quotation is more durable than a page number alone.

Use one issue per independent concern. Several observations about the same proof
can stay together; unrelated corrections are easier to track separately.

For a suggestion about the whole book, describe the change and how you think it
would help readers. Suggestions about coverage, sequencing, examples, notation,
and the relationship between the two books are all welcome.

You may include mathematical notation in Markdown, for example `$O(n \log n)$`,
and attach a screenshot of the relevant passage. Include only the material
needed to explain the report. All issue text and attachments are public.

Please keep comments specific, constructive, and focused on the material.
Assignment submissions, grading questions, and personal matters belong in your
usual private course channel. If you prefer not to use GitHub, contact a course
instructor through that channel.

Instructors with source access should propose edits through pull requests in the
private source repository. Link the public issue from the pull request, and give
the reader an accessible explanation here when the change is published. Reader
feedback does not require a fork, a pull request, or a local Git installation.
